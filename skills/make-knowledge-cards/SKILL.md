# 知识卡片制作

把一篇文章转换成 5–8 张可独立学习的知识卡片。卡片必须来自原文，宁可少而准，不要多而空。

## 输入与边界

支持：

- 用户直接粘贴的正文。
- 本地 `.md` 或 `.txt` 文件路径；完整读取后再处理。

一次处理一份输入；若给了多份，先确认要处理哪一份。

不支持网页抓取、PDF、Anki 导出和图形界面。遇到这类请求时，用一句话说明边界，并请用户粘贴正文或提供 `.md`/`.txt` 文件；不要尝试用其他工具绕过。

## 提炼流程

1. **读全**：读完整篇输入。文件内容被截断时继续读取，不要只根据开头生成。
2. **找知识点**：优先提取定义、核心主张、因果机制、方法步骤、判断标准、权衡与有依据的结论。跳过广告、寒暄、过渡、重复铺垫和只服务于一个论点的细节。
3. **去重与排序**：合并同义或反复出现的表述；删除跨卡重复的细节、例子和提醒，只保留在最相关的一张卡中；按对理解全文的重要程度排序，而不是按出现顺序。若原文有清晰结构，可沿用。
4. **定卡数**：目标 5–8 张。超过 8 个候选取最重要的 8 个，或合并高度相关的点；不足 5 个合格知识点时，有多少写多少，并在开头用一句话说明“原文信息有限，仅生成 N 张”，不要拆分、重复或补写来凑数。没有实质知识时，说明原因并停止。
5. **逐卡写作**：一张卡只讲一个知识点。标题要具体；核心知识用一句自足的话；解释说明“为什么/如何”，只使用原文信息；例子或自测二选一。

## 卡片格式

```markdown
### 1. 具体标题

**核心知识：** 一句话，独立可读。

**简明解释：** 1–3 句，说明原因、机制或用法；能用一句说清时不必凑句。

**例子：** 原文中的例子（可压缩，但不得改写事实）。
```

若原文没有合适例子，改为：

```markdown
**自测：** 一个能检验该知识点的问题。

**答案：** 依据原文作答的简短答案。
```

默认只输出卡片。信息不足时，在卡片前加一行说明；不要附加全文摘要、评价、学习计划或扩展知识。

## 忠实性要求

- 只写原文明确支持的内容。不要补充外部背景、数据、研究、案例或因果解释。
- 解释里不要补原文没有的因果、后果、对比或建议。原文只给做法时，就复述做法和条件；不要用“这样能”“否则会”“因为”自行补理由。
- 不要补原文没有的具体细节，如地点、频率、人数、工具、时长；标题和核心知识里的每个具体信息都要能在原文找到。
- 不要把相邻的两段内容拼成原文没有的比较（如“A 比 B 更重要”），除非原文明确比较。
- 保留原文的限定词（可能、通常、往往、在……条件下），不要把推测写成确定结论。
- 数字、专名、条件和结论必须与原文一致；术语沿用原文，必要时可在括号内用原文解释。
- 原文是观点或推测时，写成“作者认为/主张……”，不要当作普遍事实。
- 自测题必须能从原文作答，答案不得引入原文没有的信息。
- 不确定的内容直接省略，不要用模糊措辞掩盖。

## 完成前自检

- 是否覆盖全文最重要的知识，而不是次要细节？
- 每张卡是否只有一个知识点，且不与其他卡重复？
- 同一细节、例子或提醒是否只出现在一张卡里？
- 是否 5–8 张；若不足 5 张，是否确属信息不足而非偷懒？
- 每条解释、例子、答案是否都能在原文中找到依据？
- 是否出现了原文没有的地点、频率、原因、后果、比较或建议？
- 是否保留了原文的限定词，没有把“可能/往往”写成“一定”？
- 标题是否具体，脱离原文也能看懂？
